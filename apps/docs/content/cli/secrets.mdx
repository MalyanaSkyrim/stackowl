---
title: stackowl secrets set
description: Gives the cloud secrets of one environment their values, from .env.<environment>.
---

```sh
stackowl secrets set <environment> [--apply]
```

Instead of one `gcloud secrets versions add` per secret by hand, write the values in a local file per environment, named with the app's own variable names:

```sh title=".env.staging"
DATABASE_URL=postgresql://…
AUTH_SECRET=…
```

Then:

```sh
stackowl secrets set staging            # what is set, what would change
stackowl secrets set staging --apply    # adds a new version where the value differs
```

- The list of secrets comes from `gcp.secrets` in the config.
- A name missing from the file is left as it is.
- A required secret with no value, or still on the `placeholder`, is a problem (`✖`).
- A secret that doesn't exist yet is created, unless `gcp.createMissing` is `false`.
- Values are compared, never printed, and passed to `gcloud` on stdin, so they don't show in a process list.

Services read the latest version when a new revision starts: redeploy to pick up new values.

`.env.<environment>` files are gitignored by `stackowl init`. Keep them out of the repository. See the [gcp module](../modules/gcp.mdx).
