---
title: setupwise github vars
description: Sets the repository variables your workflows read, from the env file.
---

```sh
setupwise github vars [--apply]
```

Instead of typing them in GitHub → Settings → Secrets and variables → Actions, list the variables in the config:

```ts title="setupwise.config.ts"
github: {
  variables: {
    API_URL_STAGING: { why: 'the API staging builds call' },
    API_URL_PRODUCTION: { why: 'the API production builds call', fallback: 'https://api.example.com' },
  },
},
```

Each value comes from the env file under the variable's own name, else from `fallback`. A variable with no value anywhere is reported and left alone. A variable set on GitHub but not locally is left as it is.

Variables are readable by anyone with access to the repository. Never put a secret in one: use GitHub secrets, which SetupWise checks but doesn't set.

Needs `gh` logged in (`gh auth login`). It reads through `gh api`, so any `gh` version works.
