| Workflow               | File                    | Runs on                                                                               | What it does                                                                                                                                                  |
| ---------------------- | ----------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Continuous Integration | `ci.yml`                | Every pull request, or by hand                                                        | Spelling, formatting, types, lint, tests, build, Storybook build; checks the migrations match the Prisma schema on a throwaway CockroachDB                    |
| Infrastructure         | `infra.yml`             | Pull requests and pushes that change `infra/`, on `main` and `production`; or by hand | `tofu fmt` and validate, plan on pull requests, apply on merge                                                                                                |
| Deploy Staging         | `deploy-staging.yml`    | Push to `main`, or by hand                                                            | Calls `deploy.yml` for staging                                                                                                                                |
| Deploy Production      | `deploy-production.yml` | Push to `production`, or by hand                                                      | Calls `deploy.yml` for production                                                                                                                             |
| Deploy (reusable)      | `deploy.yml`            | Called by the two above                                                               | Checks the skip label, runs Prisma migrations with the environment's `DATABASE_URL`, then builds `api` and `web` on Cloud Build and deploys them to Cloud Run |
| Deploy Mobile (iOS)    | `deploy-mobile.yml`     | By hand only, from `main` or `production`                                             | Builds with Fastlane on a Mac runner, signs with Match, uploads to TestFlight                                                                                 |

## When a deploy skips a service

A deploy builds `api` or `web` only when something it's built from changed since the commit its Cloud Run service runs now (images are tagged with their commit). A service still on the placeholder image is always deployed. Tick **Force deploy all services** when running it by hand to skip the check.

Logging in to Google Cloud uses no stored key (Workload Identity Federation): only this repository can log in, pull requests can only plan, and only `main` and `production` can apply or deploy.
